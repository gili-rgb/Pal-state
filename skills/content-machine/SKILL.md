# מכונת תוכן v8.17 — SEO + GEO/AEO & HTML לאלמנטור

> **v8.17 (רשימת המותגים של מרום מול המציאות, 2026-08-16):** סעיף "מותגים" מנה שמונה מותגים בזמן שלמרום תנועה על **למעלה מעשרים**. הרשימה החסרה היא חלק מהסיבה שגרונדיג, אינדסיט, אמאנה, מולינקס ומג'ימיקס יושבים על אפס: `preflight` מסמן אותם כדורשים הזנת קישורים, וקובץ הפרויקט אמר שהם מחוץ לתחום. **הכרעת גיל: קיומו של עמוד מותג אינו תנאי לכתיבה** — מותג עם תוכן טוב וחשיפות מותר גם בלי עמוד `/brands/` (סמוראי, 13,416 חשיפות, הוא הדוגמה). הרשימה נבנתה מחדש ממיפוי GSC חי ומחולקת לשלוש שכבות תנועה, וההחרגות המחייבות נכתבו לצידה במקום להיסמך על הזיכרון: בקו אסורה לחלוטין למרות 12,131 חשיפות, דלונגי בלי מקררים ובלי "שירות רשמי" למכונות קפה, ומוצרים קטנים במעבדה בלבד. **חשיפות לבדן אינן מתירות כתיבה, וההחרגות הן שקובעות.** בנוסף הופרדה שכבת אלקטרוניקה שאינה שירות: הייסנס, TCL, בוס ו-JBL קיימים באתר כחלפים בלבד (שלטים לטלוויזיות, רמקולים ואוזניות) ומרום אינה נותנת להם שירות. **TCL כן מותג שירות של פלרום ולא של מרום.** ממצא: `/product-category/hisenes/` מדורג על "שירות הייסנס" במיקום 12.5, שאילתת שירות שאיננו יכולים לשרת.

### שלב 0 — Preflight (חובה, לפני כל שלב אחר)

**אל תמשוך דאטה ידנית ואל תבחר נושא. הרץ את הסקריפט.**

```bash
rm -rf /home/claude/pal-gsc /home/claude/pal-state
git clone --depth 1 https://github.com/gili-rgb/pal-gsc-data /home/claude/pal-gsc
git clone --depth 1 https://github.com/gili-rgb/Pal-state /home/claude/pal-state
python3 /home/claude/pal-state/tools/preflight.py --site [csb|marom|plrom] --phase plan
```

הסקריפט מאמת את קיום `pal_lint.py`, קורא את הלדג'ר, טוען את כל שאילתות ה-GSC של האתר, ומחזיר:

| שדה ב-brief | מה זה |
|-------------|-------|
| `allowed_topics` | **הרשימה היחידה שמותר לבחור ממנה** |
| `refresh_queue` | נושאים שמאמר קיים כבר מדורג עליהם 4-20 → Mode Refresh, לא מאמר חדש |
| `brand_hub_gaps` | פער עמוד מותג, לא פער בלוג. אל תכתוב עליהם בלוג |
| `vocabulary` | **אוצר המילים המאומת.** מונח שאינו כאן — אסור להשתמש בו |
| `h1_variants` | הווריאנטים לפי חשיפות. ה-H1 נגזר מהמוביל |

**שלוש הקריאות הנדרשות** מופיעות ב-`mcp_requests`. בצע את כולן ושמור ל-`mcp_results.json`:

| מפתח | מקור | למה |
|------|------|-----|
| `live_blog_titles` | `get_page_html` על `/blog/` | שכבת דדופ שלישית |
| `products` | `search_products` על מונח מהנושא | כרטיס Hero verbatim |
| `competitor_headings` | `web_search` על שאילתת היעד + חילוץ H2 מ-3-5 התוצאות המובילות | **רצוי ולא חובה.** מזין את `INFO_GAIN_DIFF` (WARN). **בסביבה בלי חיפוש — דלג והמשך**, הריצה אינה נחסמת |
| `brand_hub`, `verified_links` | לפי הצורך | זווית בידול, קישורים מאומתים |

ואז:

```bash
python3 /home/claude/pal-state/tools/preflight.py --site [site] --phase finalize --mcp mcp_results.json
```

**exit שאינו 0 = עצירה.** אין brief, אין כתיבה. אל תמשיך "בערך".

**חשוב, ומשפיע ישירות על אורך הריצה (v8.10):** `preflight` מייצר שני קבצים:

| קובץ | גודל | למי |
|------|------|-----|
| `brief_partial_{site}.json` | ~41KB | **זה מה שקוראים.** כל הנושאים, כל תור ה-Refresh, מחירים, נציגה, נרטיב |
| `brief_full_{site}.json` | ~192KB | **אל תקרא אותו.** מכיל את אוצר המילים; `postflight` קורא אותו לבד |

**שום נושא לא חסר ברזה.** ההבדל היחיד הוא אוצר המילים (6,235 מילים, 62KB) — הוא כלי הצלבה של `postflight`, לא חומר קריאה.

`allowed_topics_table` הוא כל 185 הנושאים בפורמט טבלאי: `topics_columns` מגדיר את העמודות, וכל נושא הוא מערך. אותם נתונים בשליש הנפח. חמשת המובילים קיימים גם כאובייקטים מלאים ב-`allowed_topics`.

**כשה-MCP אינו זמין (v8.4):** `finalize` נעצר עם רשימה מפורשת של מה חסר. `--allow-degraded` מייצר brief מסומן `degraded`, אבל `postflight` חוסם אותו ב-`DRAFT_BRIEF`. **טיוטה כזו אינה לפרסום** — היא רק לעבודה מקומית עד שהשרת חוזר.

**מה בוטל בגלל השלב הזה:** שער ה-dedup הידני (ledger + recent_chats + conversation_search + site:) הוחלף בחיסור מכני. אנטי-קניבליזציה מוכרעת לפי מיקום GSC ולא לפי שיפוט. בחירת נושא היא בחירה מרשימה, לא חיפוש.

### שלב 1 — זיהוי פרויקט

קרא את קובץ הפרויקט המתאים. חלץ: מותגים, קישורים אסורים, CTA links, ערוץ YouTube, פרטי ארגון. (נתוני GSC כבר נטענו בשלב 0 מה-repo, ומוצרים/קישורים נמשכים מ-WooCommerce MCP.)

### שלב 2 — בחירת נושא (מתוך ה-brief בלבד)

**אל תחפש נושא. בחר מ-`allowed_topics` שהתקבל בשלב 0.**

הרשימה כבר עברה את כל השערים: הלדג'ר, מיקום ה-GSC של מאמרי בלוג קיימים, וכותרות הבלוג החיות. נושא שאינו ברשימה נפסל מסיבה מתועדת ב-`refresh_queue` או ב-`brand_hub_gaps`.

**כלל הבחירה:** הפריט עם החשיפות הגבוהות ביותר, אלא אם יש סיבה עסקית מפורשת לבחור אחר. דווח את הבחירה ואת הסיבה בשורה אחת, בלי סימן שאלה ובלי המתנה.

**`refresh_queue` = Mode Refresh, לא מאמר חדש.** מאמר בלוג קיים מדורג 4-20 על השאילתה, ולכן יצירת מתחרה תפצל את האות. עדכן את הקיים: תוכן, FAQ מיהלומי Bing, קישורים פנימיים, `dateModified` ו-`.last-updated`. ה-URL נשמר.

**`brand_hub_gaps` = לא נושא בלוג.** שאילתה בלי אות כוונה ("מילה שירות לקוחות", "bsh") היא פער עמוד מותג. העבר ל-brand-hub-machine.

**הבסיס לכך שהחלטת הקניבליזציה היא מיקום ולא חפיפה:** מחקר אהרפס על 80 מילות מפתח עם דירוגים מרובים מצא מקרה אחד שדרש טיפול. חפיפת שאילתות היא ברירת מחדל בריאה באשכול. הסימן לבעיה הוא כוונה זהה ועמוד שכבר מחזיק את המיקום.

### שלב 2ב — Mode Refresh (כשהנושא מגיע מ-`refresh_queue`)

**רענון אינו כתיבה מחדש.** העמוד כבר מדורג 4-20 ומביא תנועה. המטרה היא להוסיף כיסוי בלי לפגוע במה שעובד.

**מה ה-brief נותן לכל עמוד בתור:**

| שדה | מה לעשות איתו |
|------|---------------|
| `ranking_for` | מה העמוד כבר מנצח בו. **אל תיגע בסעיפים שמכסים את אלה** |
| `gap_queries` | ביקוש אמיתי במיקום 11-40. **כאן מוסיפים תוכן** — H2 חדש לכל אחת |
| `triggers` | השאילתות שהעלו את העמוד לתור |
| `existing_h1` | ה-H1 הקיים |
| `total_impressions` | סדר גודל התנועה. התור ממוין לפיו |

**קדוש, אסור לגעת (`frozen`):** ה-URL, ה-slug, `datePublished`, וה-`@id` של כל הישויות. שינוי URL הורג עמוד שמדורג במקום 5.

**חובה לעדכן:** `dateModified` ו-`.last-updated` לתאריך היום.

**H1:** נשאר, אלא אם הוא בדפוס ליסטיקל — ואז מותר לשכתב אותו לפורמט הד-לשאילתה.

**מה מוסיפים בפועל:**
1. **H2 לכל `gap_query` משמעותית**, בפורמט Answer-First
2. הרחבת FAQ ביהלומי Bing ו-PAA חדשים
3. קישור ל-`/brands/` אם חסר
4. הסרטון מה-brief אם קיים ולא מוטמע
5. חיזוק קישורי אשכול

**מה שלא עושים:** לא מוחקים סעיפים קיימים, לא משנים את הנרטיב, ולא "מסדרים" מבנה שעובד.

`postflight` אוכף: `REFRESH_DATE` (ERROR, התאריך לא עודכן), `REFRESH_URL_CHANGED` (ERROR, ה-slug נעלם), `REFRESH_NO_GAIN` (WARN, אף שאילתת פער לא כוסתה — רענון בלי כיסוי חדש אינו משפר דירוג).


### שלב 3 — קישורים פנימיים (מפת קישורים)

בנה מפת קישורים פנימית מלאה לכל מאמר. כל הקישורים נמשכים מ-WooCommerce MCP (שלב 0), **permalink verbatim** (כלל הברזל המלא בשלב 0).

**תקציב קישורים — 4-7 קישורים פנימיים בגוף המאמר:**
1. **קטגוריית אב רלוונטית** — מ-`get_categories` (csb/plrom; **במרום — משדה `categories` בתוצאות `search_products`, לא get_categories**). בחר את הקטגוריה המדויקת לנושא (לא הכי כללית), permalink verbatim. זה צומת ה-hub שמחלק equity.
2. **3 מוצרים** — מ-`search_products` לפי נושא/מותג, קישורים ישירים בגוף.
3. **Hero Product** — כרטיס מוצר (שלב 7).
4. **Cluster** — pillar + 2 siblings (שלב 6).
5. **עמוד המותג (brand hub)** — אם קיים עמוד מותג למותג הנדון, קישור אחד אליו חובה (בגוף או בפסקת "מאמרים קשורים"). זה צומת הסמכות החזק ביותר לנושא. הרשימה per-site: זיכרון מובנה, סעיף "PPM internal brand-hub links" (מקור יחיד, לא משוכפל לכאן).

**משמעת anchor:** הכללים המלאים ב-`common-core.md` סעיף 4 (תיאורי, שפת לקוח, מגוון, עוגנים אסורים). pal-lint v1.3.0 אוכף.

**גיבוי אם WooCommerce MCP לא מחזיר:** חפש `site:[domain] [נושא]` ב-web_search ואמת כל קישור לפני שימוש. **לעולם לא להמציא קישורים ולעולם לא לבנות אותם מתבנית.**

### שלב 4 — Community Mining + מחקר H1

**שלב אחד, שתי מטרות:** גילוי שאלות אמיתיות בשפת הלקוח + מציאת ה-H1 המדויק. השתמש קודם בשאלות מ-gsc_customer_language.md וב**יהלומי Bing**, ואז העשר ב-web_search.

**⚠️ כלל ברזל — אימות permalink של blog posts (נוסף יוני 2026):**
blog posts אינם במאגר ה-MCP. לכן **אסור לבנות slug מהכותרת** ואסור לסמוך על web_search בלבד.
לכל blog post שמקשרים אליו — חובה להריץ `check_url` (WooCommerce MCP) על ה-URL שנמצא בחיפוש ולחלץ את שדה `canonical`. ה-canonical הוא ה-permalink הנכון. `web_fetch` רק אם `check_url` נכשל (v7.18).

```
# תהליך אימות permalink לכל blog post:
1. web_search → מקבל URL (עשוי להיות percent-encoded)
2. `check_url` על אותו URL
3. חלץ את שדה canonical מה-metadata
4. ה-canonical = permalink שנכנס לבלוג
```

**דוגמה לטעות:** כותרת "מייבש בלומברג תקלות: 7 בעיות נפוצות" → slug שגוי `/מייבש-כביסה-בלומברג-תקלות-7-בעיות-נפוצות/` → canonical בפועל `/מייבש-כביסה-בלומברג-תקלות-7-בעיות-נפוצו/` (וורדפרס חותך slugs ארוכים). בלי אימות canonical — קישור שבור.

**עברית + שפה לא פרסומית + Anti-Pattern + שפת לקוח:** הכל ב-`master-prompt.md` — כללי ברזל, מונחים קבועים (ספוג/קצף, צוקל/פלינטוס, מקרר/פריג' ועוד), איסור מקף ארוך, רשימת השפה הפרסומית האסורה, טבלת שפת לקוח מלאה, וגיוון מבני. הצלב כל מונח מול gsc_customer_language.md לפני הגשה: לא מופיע שם = כנראה שפת יצרן, החלף.

**משמעת מילות קישור (v7.20, כלל כתיבה מחייב):** Yoast מודד רק אחוז, ולכן טקסט יכול להיות ירוק ב-30-45% ועדיין להיקרא מכני. שלוש מגבלות:
